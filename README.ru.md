## Продвинутые возможности

### Конвертация валют в реальном времени

Проект интегрирован с API курсов валют и динамически конвертирует стоимость подписок в зависимости от выбранного языка и валюты.

Система конвертации тесно связана с i18n-архитектурой проекта и обеспечивает более реалистичный и локализованный пользовательский опыт.

Реализовано:

- Интеграция с реальным API
- Динамическая конвертация валют
- Локализованное форматирование цен
- Асинхронная загрузка данных
- Обработка ошибок и состояний загрузки
- Переиспользуемая hook-архитектура

---

### Эмуляция Data Layer

Проект имитирует архитектуру frontend-приложения с реальным backend API.

Вместо простого хардкода интерфейс использует структурированные типизированные сущности и переиспользуемые модели данных для:

- Фильмов
- Сериалов
- Категорий
- Жанров
- Навигационных секций
- Подписок

Такой подход делает архитектуру проекта ближе к production-ready приложениям.

---

### Переиспользуемая система слайдеров

Проект содержит собственную abstraction-обертку над Swiper.

Система поддерживает:

- Общую конфигурацию по умолчанию
- Гибкое переопределение параметров
- Кастомную пагинацию
- Кастомный scrollbar
- Навигационные элементы
- Адаптивные breakpoints
- Контроль overflow-поведения

Это позволяет масштабируемо переиспользовать слайдеры в разных секциях приложения без дублирования конфигурации.

### Skeleton Loading System

В проекте реализована система skeleton loading для асинхронных UI-секций, получающих данные из API.

Вместо обычных spinner-лоадеров интерфейс отображает адаптивные skeleton-placeholder элементы, сохраняющие структуру layout и улучшающие восприятие скорости загрузки.

Реализовано

- Переиспользуемые skeleton-компоненты
- Сохранение структуры интерфейса во время загрузки
- Интеграция с асинхронным API
- Улучшенный UX во время загрузки данных
- Адаптивные skeleton-layouts
- Специализированные loading states для разных секций

Такой подход делает интерфейс более отзывчивым и ближе к production-grade стандартам пользовательского опыта.

## Ключевые инженерные решения

### Почему Typed Routing?

Типизированный роутинг помогает избегать ошибок при навигации и упрощает поддержку приложения во время рефакторинга.

---

### Почему собственная abstraction над Swiper?

Вместо дублирования конфигурации слайдеров по всему проекту используется единая переиспользуемая обертка с централизованными настройками и гибкой кастомизацией.

---

### Почему Config-Driven Navigation?

Навигационная структура полностью отделена от UI-логики, что делает систему более масштабируемой и удобной для поддержки.

---

### Почему используется эмуляция Data Layer?

Проект намеренно имитирует архитектуру frontend-приложения с backend API, чтобы приблизить структуру приложения к реальным production-практикам разработки.
